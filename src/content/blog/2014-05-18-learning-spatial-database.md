<p>A while ago I was asked a question about Spatial database and figured out I didn't know anything about it. So, I use this platform to document my learning about this topic.</p><p><strong>What is Spatial data?</strong></p><p>The first lesson in "database 101" is that the design of a database should fit to the queries made on it. The special thing about spatial databases is that they hold data about objects in a geometric spaces. Most of the traditional databases don't index the information in an optimize way for spatial queries, examples for such queries can be -</p><ul><li>How to far is location A to location B?</li><li>How to get from location A to location B?</li><li>What is the closest restaurants to some location?</li><li>What is the path people usualy take in some park \ market?</li><li>Is location A inside city B?</li></ul><p>We can divide spatial queries to few groups (based on <a href="http://en.wikipedia.org/wiki/Spatial_database#Features_of_spatial_databases">Wikipedia</a>)</p><ul><li><span style="text-decoration:underline;">Spatial Measurements</span>: Computes line length, polygon area, the distance between geometries, etc.</li><li><span style="text-decoration:underline;">Spatial Functions</span>: Modify existing features to create new ones, for example by providing a buffer around them, intersecting features, etc.</li><li><span style="text-decoration:underline;">Spatial Predicates</span>: Allows true/false queries about spatial relationships between geometries. Examples include "do two polygons overlap" or 'is there a residence located within a mile of the area we are planning to build the landfill?'</li><li><span style="text-decoration:underline;">Geometry Constructors</span>: Creates new geometries, usually by specifying the vertices (points or nodes) which define the shape.</li><li><span style="text-decoration:underline;">Observer Functions</span>: Queries which return specific information about a feature such as the location of the center of a circle.</li></ul><p><strong>What is next?</strong></p><p>This post is actually the preview for additional two posts - a theoretic one and a productive one.</p><p>The theoretic one will compare the different spatial indices and on which needs each of them answers. This post will talk about the most common index of this kind is R-Tree and some of its' extensions and presumably some additional related theory.</p><p>The productive one will present some of the current solutions for spatial data among them is <a href="http://postgis.net/">PostGis</a> used in PostgreSQL, MySQL and additional NoSQL solution (probably either Neo4j or MongoDB).</p><p>Beside the basic curiosity of learning a new thing I believe that the field of "Location intelligence", i.e., using and analyzing spatial information as part of the decision making process, is an emerging field yet to be discovered. In other words location intelligence is another layer of business intelligence (BI) and as the technology evolves and the data is gathered we can now use this data better than ever before.</p><p>Some of the current commercial application of location intelligence - </p><ul><li>Route planning - such as <a href="https://www.waze.com/">Waze</a></li><li>Geo targeting - for example using IP address to display relevant ads. </li><li>Travel planning - hotel, restaurant, attractions such as <a href="http://www.getyourguide.com/">GetYourGuide</a></li><li>Sales analysis - such as <a href="http://www.spatialkey.com/spatialkey_platform.php">SpatialKey</a></li></ul><p> </p>
